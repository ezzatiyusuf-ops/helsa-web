۱معرفی پروژه و معماری

سایت هلسا ایرانیان، فروشگاه آنلاین محصولات طبیعی (خرما، شکلات دست‌ساز خرما، آجیل، خشکبار، مربا و دمنوش‌ها) به‌همراه «مرکز سلامت» (مقالات، راهنمای محصولات، پادکست و ویدیاکست) است. سایت همزمان یک PWA (وب‌اپ قابل نصب روی موبایل) کامل است.

گام‌به‌گام

گام ۱ — پکیج کامل را Extract کنید (مثلاً در D:\helsa).

گام ۲ — نصب وابستگی‌ها در PowerShell (داخل پوشهٔ پروژه):

npm install

گام ۳ — ساخت دیتابیس (در SQL Shell پستگرس — پسورد نصب را وارد کنید):

CREATE USER helsa WITH PASSWORD 'helsa_dev_pw'; CREATE DATABASE helsa_db OWNER helsa; \q

گام ۴ — بازیابی داده‌ها از فایل دامپ (در PowerShell معمولی):

$env:PGPASSWORD='postgres' psql -U postgres -h localhost -d helsa_db -f "D:\helsa\helsa-db-backup.sql"

گام ۵ — ساخت فایل .env: از .env.example کپی بگیرید و حداقل این‌ها را ست کنید:

DATABASE_URL=postgresql://helsa:helsa_dev_pw@localhost:5432/helsa_db NEXT_PUBLIC_SITE_URL=http://localhost:3000

گام ۶ — اجرا:

npm run dev ← حالت توسعه (تغییرات فوری دیده می‌شود) :: یا پروداکشن محلی: npm run build npm start
✔ تست موفقیت صفحهٔ اصلی باز شود، بخش «هلسا در شبکه‌های اجتماعی» پست‌ها را نشان دهد و صفحهٔ محصولات ۱۶ صفحه و ۱۸۴ محصول داشته باشد = همه‌چیز درست است.
⚠ مهم‌ترین نکتهٔ این فصل تقریباً همهٔ مشکلات رایج (محصولات ۳ صفحه‌ای، خالی‌بودن بخش سوشال) به یک علت برمی‌گردد: دیتابیس روشن نبودن. قبل از اجرا مطمئن شوید سرویس PostgreSQL ویندوز در حال اجراست (services.msc → postgresql-x64-17).

ورود

آدرس /admin — ورود با ایمینی که در متغیر ADMIN_EMAILS فایل .env ثبت شده است (کد تأیید OTP پیامکی؛ برای محلی بدون سرویس پیامک، حالت تست در .env.example توضیح داده شده). هیچ‌کس جز ایمیل‌های این لیست به پنل دسترسی ندارد.

جریان خرید

انتخاب محصول ← سبد خرید ← ورود/ثبت‌نام (OTP) ← آدرس و ارسال ← پرداخت در درگاه بانکی ← بازگشت به سایت و ثبت سفارش ← پیگیری از /account. هر جریان به‌صورت E2E تست شده است (اسکریپت‌های scripts/qa-psp.py).

⚠ قانون طلایی منطق پرداخت هرگز mock نمی‌شود و درگاه فقط با env سوییچ می‌شود. قبل از لانچ، یک پرداخت واقعی کوچک (مثلاً ۱۰,۰۰۰ ریال) انجام دهید و برگشت وجه آن را تست کنید.

۷PWA و اپ موبایل

سایت هلسا یک وب‌اپ کامل (PWA) است؛ کاربران می‌توانند آن را مثل اپ نصب کنند — بدون گوگل‌پلی و اپ‌استور:

اندروید (کروم)

پس از ۱۲ ثانیه حضور در سایت، نوار «نصب اپلیکیشن هلسا» ظاهر می‌شود و با یک ضربه نصب می‌شود. آیکون، صفحهٔ اسپلش و شورتکات‌ها (محصولات / سینی مزه / سبد خرید) از قبل پیکربندی شده‌اند.

آیفون (سافاری)

iOS رویداد نصب خودکار ندارد؛ نوار راهنمای اختصاصی نمایش داده می‌شود: «اشتراک‌گذاری ← افزودن به صفحهٔ اصلی». (این راهنما در سافاری و فقط اگر اپ نصب نشده باشد، حداکثر یک‌بار در ۳۰ روز می‌آید.)

سرویس‌ورکر (نسخهٔ helsa-v3)

  • کش هوشمند: فایل‌های ایستا از کش (سریع)، صفحات از شبکه با fallback آفلاین
  • به‌روزرسانی: با انتشار نسخهٔ جدید، نوار «نسخهٔ جدید هلسا آماده است» ظاهر می‌شود — بدون رفرش اجباری
  • بستن هر نوار = سکوت ۳۰ روزه (تجربهٔ غیرمزاحم)
✔ بعد از انتشار تغییر بزرگ اگر کاربران نسخهٔ قدیمی می‌بینند، عدد VERSION در public/sw.js را یک رقم بالا ببرید (مثلاً helsa-v4) تا کش‌های قدیمی در اولین مراجعه خودکار پاک شوند.

۸استقرار آنلاین (دیپلوی)

مسیر توصیه‌شده: GitHub → Netlify (خودکار)

  1. پروژه را در GitHub push کنید (repo خصوصی)
  2. در Netlify: «Add new site → Import an existing project» و repo را انتخاب کنید
  3. فایل netlify.toml از قبل در پروژه است — نیازی به تنظیم بیلد نیست
  4. متغیرهای محیطی را در Site settings → Environment variables وارد کنید (حداقل: DATABASE_URL، NEXTAUTH_SECRET، NEXTAUTH_URL، کلیدهای درگاه و پیامک)
  5. از این به بعد هر push = دیپلوی خودکار

نکات مهم استقرار

  • بیلد بدون دیتابیس هم موفق است (صفحات داده‌محور dynamic هستند) — ولی برای اجرای کامل، DATABASE_URL هاست واقعی (مثل Neon/Supabase) لازم است
  • دامنهٔ اختصاصی: Site settings → Domain management → دامنه را اضافه کنید؛ SSL خودکار فعال می‌شود
  • قبل از اتصال دامنه، NEXT_PUBLIC_SITE_URL و NEXTAUTH_URL را روی آدرس نهایی بگذارید
  • دیتابیس ابری را با همان فایل helsa-db-backup.sql پر کنید

۱۰عیب‌یابی رایج

مشکلعلتراه‌حل
